Abstract

The Smart Digital Wellbeing Platform is a comprehensive, multi-tier analytics and tracking system designed to streamline, categorize, and optimize users' digital habits. The system bridges the gap between raw browser telemetry and actionable productivity insights, enabling individuals to seamlessly monitor their online habits without relying on manual entry constraints.

The system is built on a highly robust Node.js backend utilizing Express.js and WebSockets, with SQLite managed through Prisma ORM for embedded, efficient persistent storage. The frontend adopts a modern React ecosystem utilizing Recharts for data visualization, while a sophisticated Native WebExtension (MV2) written in JavaScript serves as the core data ingestion pipeline natively bridging Mozilla Firefox and Google Chrome.

The platform autonomously categorizes domain visits dynamically using an advanced RegEx dictionary matching engine and contextual tab titles, correctly mapping specialized learning environments out of naturally distracting domains (e.g., YouTube tutorials). The platform efficiently handles offline-capable queue batching, independent multi-device tracking, sleep-resistant heartbeat algorithms to circumvent OS-level idle timeouts, and real-time frontend updates over dedicated TCP sockets.

This report documents the architectural design, algorithmic modules, classification formulas, extension integration strategies, and the robust scalable systems underpinning the Smart Digital Wellbeing Tracker.

1. Introduction

1.1 Problem Statement

In an increasingly digital world, individuals are constantly exposed to digital distractions. Traditional tracking tools often rely heavily on manual user logging or crude domain-blocking algorithms that fail to account for context (e.g., classifying all of YouTube as distracting, even when the user is watching an educational course). Furthermore, native browser histories fail to unify sessions across multiple computers or seamlessly categorize them into productivity matrices in real-time.

1.2 Project Objectives

  • Develop a centralized, multi-tier digital wellbeing tracking system operating completely natively across the host browser.
  • Implement an intelligent context-aware classification algorithm relying on regex boundaries rather than raw, lag-heavy third-party LLM algorithms.
  • Build a real-time, zero-flicker Data Dashboard allowing users to visualize daily, weekly, and peak-hour statistics dynamically.
  • Circumvent operating system "sleep/idle" delays via strict Application-layer pings ensuring session times precisely reflect reality.
  • Construct a highly available backend WebSocket architecture matching active domains across different isolated machines and browser profiles concurrently.

1.3 Scope of the Project

The Smart Digital Wellbeing Tracker covers the following core areas:

  • Cross-browser Extension capable of securely generating unique device schemas and tracking URL/Window modifications.
  • Intelligent Data Heuristics calculating total productivity scores mapped against Distracting, Learning, Productive, and Neutral states across raw timestamps.
  • Dynamic UI Dashboard aggregating Live Tabs and generating dynamic Recharts for activity heatmaps.
  • RESTful API backend handling strict token generation and batch telemetry data syncing.

4. System Architecture

4.1 Overall Architecture

The platform is fully decoupled. The React Dashboard and MV2 Extension act strictly as clients routing requests towards the core Express logic processor. The components relay states simultaneously: when the Extension notices a tab switch, it pipes the telemetry via HTTP POST requests for history logging, while sending concurrent WebSocket pings explicitly identifying real-time UI modifications matching its localized unique device identifier.

4.2 Backend Architecture

The backend operates via a multi-layered MVC paradigm:

  • Event Processors: Catch tabs_update, auth, and ping structures routing them to unified client hash-maps.
  • Analytics Routers: Compute complex Daily, Weekly, Streaks, and Peak hour structures actively relying on localized algorithmic loops bypassing direct SQL aggregations if they bottleneck.

4.3 Frontend Architecture

The dashboard renders from a nested React Tree mapping context variables:

  • DashboardPage.jsx: The mastermind controller component. It performs silent 10-second background polling utilizing date triggers, passing cached results explicitly as Prop trees down into dynamic Recharts avoiding loading-screens.
  • LiveTabs.jsx: Establishes an independent WebSocket connection directly matching UI render layouts alongside specific deviceId UUID keys ensuring dual-Firefox profiles do not recursively overwrite memory properties natively.

4.4 Extension Architecture

The Extension operates invisibly in the browser's background leveraging Manifest hooks:

  • listeners: Reacts to tabs.onUpdated, tabs.onCreated, windows.onFocusChanged.
  • SessionManager: Calculates boundaries and executes offline caching in case the remote API drops effectively persisting all log data.

5. Database Design

5.1 Entity Relationship Overview

The persistence layer utilizes Prisma. Activities are written chronologically and subsequently squashed and joined natively by the Analytics engine to form the Daily Summary caches linking specifically to User authorization tokens natively.

5.2 Prisma Schema Summary

  • Model: User -> Fields: id, email, password, createdAt
  • Model: ActivityLog -> Fields: id, userId, domain, title, durationSeconds, category, timestamp. Relation: Linked definitively via User. Serves as the native immutable ledger of time.
  • Model: DailySummary -> Fields: id, userId, date, totalTime, score, learningTime. Relation: Linked via User. An active computed cache representing an overarching aggregated window, preventing the system from recalculating thousands of raw ActivityLogs dynamically per second.
  • Model: CustomCategory -> Fields: id, userId, domain, category. Relation: Unique overrides. If populated, physically intercepts matching algorithms enforcing explicitly defined categories statically.

6. Core Module Design

6.1 Classification Engine (Heuristics)

To prevent processing lag from original Gemini LLM methodologies, a standalone high-speed module executes inside the Node boundary. The system tests explicit Domains (e.g., coursera.org = 0.95 Learning). For ambiguous URLs like youtube.com, the engine processes the title string utilizing isolated Regex boundaries matching instances like `/\btutorial(s)?\b/i` or `/\bcode review\b/i` resulting in instant categorical mapping avoiding false negatives implicitly.

6.2 Analytics & Heartbeat Module

The algorithm explicitly weighs tracking logic utilizing modified metrics mathematically. "Learning" intervals positively stack the total Productivity metric completely uniformly (+1.0 point), while "Neutral" environments possess a 50% passive penalty multiplier, guaranteeing that searches and basic reading loops do not unjustly punish the user's ratio against hardcore "Distracting" contexts.

6.3 Multi-Device Synchronization

Firefox processes are natively isolated per explicit profile. The extension embeds UUID-generated hashes directly into browser.storage.local contexts. When an extension boots up, it pings the server with its auth token alongside its specific Unique ID metric. The server arrays them securely separating instances terminating any ghost TCP sockets resulting from improper sleeps.

7. API Route & WebSocket Reference

9. System Optimizations & Bug Resolutions

  • Socket Death Spirals: Background extensions operating in headless states typically bypass responding to specific TCP-layer pings triggering organic server drops. Rewrote the interval algorithms explicitly pushing Application-layer `type: "ping"` strings ensuring continuous tracking.
  • Sleep-State False Additions: Replaced hardcoded MAX_SESSION caps causing legitimate binges to be deleted. The system actively runs 15-second logical tics modifying precise bounding times gracefully clipping the end state automatically upon System hibernation cycles natively removing manual pausing burdens.
  • Media State Preservation: Bypassed organic OS "Idle" triggers precisely isolating `tab.audible` streams natively verifying boolean truth outputs correctly ensuring users watching educational clips perfectly log intervals accurately avoiding automated disconnection routines dynamically.
  • Retroactive Categorization Sweeps: Engineered REST logic ensuring any categorical UI switches accurately rewind the Database caches forcefully updating historic telemetry mapping UI metrics perfectly globally immediately seamlessly.
