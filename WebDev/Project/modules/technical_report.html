Technical Report: Smart Digital Wellbeing Platform

Project: Smart Digital Wellbeing Tracker

Date: April 9, 2026

1. Executive Summary

The Smart Digital Wellbeing Platform is a multi-tier, real-time analytics suite designed to monitor, classify, and visualize browser-based user activity. Built to combat distractions and encourage productive habits, the platform seamlessly integrates a native browser extension with a Node.js backend and a React-powered analytics dashboard. It features advanced heuristic categorization, streak tracking, intelligent context evaluation, and real-time live synchronization mechanisms prioritizing both privacy and speed.

2. System Architecture

The system is comprised of three core modules communicating synchronously over REST APIs and WebSocket protocols:

  • Backend (Node.js/Express): Serves as the central command architecture. It utilizes SQLite alongside the Prisma ORM for highly efficient localized data storage. The backend handles REST endpoints, secure JWT authentication, advanced analytics endpoints, and WebSocket payload marshaling.
  • Dashboard (React/Vite): A highly responsive UI presenting activity heatmaps, category distributions, productive streaks, and the "Live Tabs" module. It retrieves aggregated data silently in the background alongside WebSocket device state payloads to provide flicker-free live updates.
  • Browser Extension (MV2 WebExtension): A native data-ingestion pipeline installed in Firefox/Chrome. Built with background service workers, it monitors tab allocations, URL transitions, audio outputs, and idle system states.

3. Key Features & Implementation

3.1 Advanced Heuristic Classification Engine

Replaced early reliance on external API calls with a highly optimized embedded RegEx dictionary matching engine (`classifier.js`). The engine evaluates domains and uses title-context heuristics (e.g., matching "React Course" vs "Funny Cats" on YouTube) to dynamically alter the final tracked category (Learning vs Distracting) with extreme speed.

3.2 Robust Sleep-Resistant Heartbeat Tracking

Circumvented native browser idle timeouts and operating limits by introducing a 15-second tracking heartbeat. Through Application-Layer Pings (`type: ping`), headless browser socket drops were completely resolved. This ensures that users partaking in multi-hour focused sessions aren't punished with truncated graphs, while automatically slicing away anomalous time padded by laptops entering sleep modes.

3.3 Real-Time Multi-Device Synchronization

Implemented deduplicated WebSocket data streams binding individual device instance hashes (`deviceId`) safely to the user's Dashboard. This permits active monitoring across multiple separate computers or profiles independently, mapping active domains and tabs inside a collapsible, non-colliding UI.

3.4 Weighted Productivity Algorithms

Integrated a mathematically balanced Productivity Score loop inside the analytics daemon. To prevent 'Neutral' search activities or 'Learning' assignments from punishing users, the algorithm applies a 100% positive modifier to 'Learning' and a flexible 50% modifier to 'Neutral' activities, enabling organic growth while preventing algorithmic staleness.

3.5 Retroactive Memory Operations

Empowered users to manually override heuristic tagging operations (e.g. permanently tagging a site as Productive). These localized DB actions retroactively iterate across the user's historical SQLite database cache, explicitly coercing old data points to match the revised rules and physically demolishing/regenerating the UI's Daily Summary cache for universal UI parity.

4. Technical Retrospective & Scalability

The current architecture proves incredibly stable resulting in zero active unhandled errors across Node and React spaces while keeping a negligible CPU footprint.

Future architectural enhancements identified for subsequent versions include introducing Batch Query network transmission loops (minimizing POST floods during offline caching), integrating Title string redaction natively inside the extension for absolute banking/privacy adherence, and writing nocturnal database cron-jobs linking daily events into unified `DailyAggregate` records for O(1) fetch times over the years.
